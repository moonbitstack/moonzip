Thirteen formats, one per package, each with the interface its own specification argues for. DEFLATE, gzip, zlib, zip, tar, lz4, snappy, LZMA, xz, bzip2, 7z, zstd, brotli — readers that check what they read, writers that stream, and no dependency beyond moonbase.

01 — InstallThree lines, then a stream.

Every package is named after the format it implements. Add the module, import the package you need, and the function names are the ones the specification uses — gzip, gunzip, tar, untar.

moon.mod
import { "moonbitstack/moonzip" }
a gzip round trip
let packed = @gzip.gzip(b"the body"[:])
let back   = @gzip.gunzip(packed[:])
a body that arrives in pieces
// Nothing is held whole: the only state between calls is the 32 KiB window
// the compressor needs and four bytes of running checksum.
let writer = @gzip.Writer::new(level=9)
for part in parts {
  for b in writer.push(part) { out.push(b) }
}
for b in writer.finish() { out.push(b) }
an archive
let archive = @zip.zip([
  @zip.Entry::new("readme.txt", body),
  @zip.Entry::new("data/table.csv", table),
][:])

// or the same thing, one member at a time
let w = @zip.Writer::new(password="a password")
w.add(entry)   // returns that member's bytes now
w.finish()     // returns the directory at the end

02 — The formatsWhat is here, and what is not.

A format is either implemented or it is not; there is no "mostly". The table says which of the two, and the notes say what the hard part was. Nothing in the library is a stub that returns its input.

PackageSpecificationReadWriteNotes
deflateRFC 1951 yesyes All three block types, both ways. The writer measures fixed, dynamic and stored per block and keeps the smallest.
gzipRFC 1952 yesyes Header fields, the header's own CRC, the trailing CRC-32 and length. Streaming via Writer/Reader.
zlibRFC 1950 yesyes Adler-32, the window the header names, the check bits.
zipAPPNOTE 6.3 yesyes Zip64, data descriptors, ZipCrypto, a reader that walks local headers from the front. AES is not implemented; it is the one gap and it is named here rather than discovered later.
tarPOSIX pax yesyes ustar, pax extended headers, GNU long names on read. Symbolic links, directories, base-256 numbers. targz is the archive through gzip.
lz4block + frame yesyes Both formats, with xxHash-32 for the header and content checksums and skippable frames stepped over.
snappyblock + framing v2 yesyes Both formats, masked CRC-32C per chunk, skippable and unskippable chunk ranges both honoured.
lzmaLZMA SDK yesyes The range coder and the probability model, and the .lzma container both ways — including the end-marker form Python writes and ours never does.
xzxz file format yesyes LZMA2 chunks, CRC-32/CRC-64/none checks, the index and the footer. Verified both ways against Python's lzma.
bzip2bzip2 yesyes Burrows-Wheeler, move-to-front and six Huffman tables, both directions — verified against libbz2, which is what Python's bz2 calls.
brotliRFC 7932 yesyes Block types, four context modes, and the 122 KB static dictionary with its 121 transforms — verified against libbrotli at qualities 0 to 11. The writer is a plain LZ77 encoder: no dictionary, no context modelling.
zstdRFC 8878 yesyes The full reader — FSE, Huffman literals in one or four streams, every table mode, repeat offsets — verified against libzstd. The writer uses the predefined tables and raw literals.
7z7z format yesyes Folders of coders over COPY, LZMA, LZMA2, BZIP2, DEFLATE and delta — read from real 7-Zip archives, including ones whose directory is itself compressed. AES, the branch filters and BCJ2 are refused by name.

A format that is not implemented is refused by name, with the method number, rather than guessed at. zip takes a Codec so a method a caller has implemented elsewhere can be plugged in without an edit to the package.

03 — StreamingThe body never has to be in one piece.

A response body arrives in chunks. A file is read four kilobytes at a time. A streaming interface means the caller never has to gather the whole thing, and the only state kept between calls is the window a back-reference can reach.

the shape
// compressor
w.push(chunk)   → the bytes that are ready (maybe none)
w.finish()      → the rest, plus the trailer

// decompressor
r.push(chunk)   → the bytes it decoded, possibly across a symbol
r.finish()      → the rest, and the trailer is checked here
what a chunk boundary may fall inside
  • A header field. Status lines, file names, pax records. The reader gathers until the header is complete, with a bound so a stream that never ends is refused rather than buffered forever.
  • A Huffman code. The decoder never consumes half a symbol and waits: eight bytes of buffered input cover the widest step, and with fewer than that it stops.
  • A stored block. The payload is copied straight out of the buffer, and a chunk boundary in the middle of one is ordinary.
  • A data descriptor. When an entry's sizes follow its data, the DEFLATE stream itself says where it ended, and the descriptor is read from there.
what the tests do

Every streaming test feeds the same body in one, two, three, five, seven, thirteen, sixty-four, five-hundred-and-eleven, four-thousand-and-ninety-six and sixty-five-thousand-five-hundred-and-thirty-six byte pieces, and requires the same bytes out each time. The boundaries that break a naive decoder are never the round ones.

06 — ProofAgreeing with itself is not enough.

A compressor that only ever reads its own output can be consistently wrong for years. Two scripts make that impossible to get away with, and CI runs both on every push.

others read what we write

scripts/conformance.py takes every stream examples/vectors prints and hands it to an independent reference decoder. Every combination of level, block type, chunk size, Zip64, descriptor and password has to come back as the body it started from.

we read what others write

scripts/interop.py writes archives with the platform's standard archive writers — the plain form, one with data descriptors because the sink it wrote to could not seek, a forced Zip64 header, and tar in ustar, pax and GNU — and pins them as tests. They are the shapes our own writer would never produce.

the gate
  • moon check --target all --deny-warn — four backends, and a warning is an error.
  • moon test --target all — the same tests on wasm, wasm-gc, js and native.
  • moon fmt, then git diff --exit-code — formatting is not a matter of taste here.
  • moon info, then git diff --exit-code — the interface is checked in, so a change to it shows up in the diff.
